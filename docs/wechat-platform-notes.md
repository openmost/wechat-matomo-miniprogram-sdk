Verified on 2026-09-28 against developers.weixin.qq.com. The SDK design tolerates both outcomes of
each item; this file records which one is true today.

**Method note:** most of the individual API pages under `developers.weixin.qq.com/miniprogram/dev/api/...`
are client-rendered SPA pages. WebFetch on those URLs returned only the site navigation shell, not the
article body, for every page listed below except `devtools/npm.html` and `reference/scene-list.html`
(both of which rendered fully). For the rest, findings below come from WebSearch results that quote or

this way, the cell says "not stated on page" and names what was checked.

| Component used as page: lifecycle in `methods`                  | Confirmed. The `Page()` reference states lifecycle callbacks may be declared "在 `Component` 构造器的 `methods` 导出方法中" — i.e. when a page is authored with `Component()` (页面级自定义组件), the full page lifecycle (`onLoad`, `onShow`, `onReady`, `onHide`, `onUnload`, `onPullDownRefresh`, `onReachBottom`, `onPageScroll`, `onShareAppMessage`, `onShareTimeline`, `onResize`, `onTabItemTap`, `onSaveExitState`, `onAddToFavorites`, `onRouteDone`) is placed inside `methods`, exactly like a normal `Page()` definition. This is distinct from `pageLifetimes` (`show`/`hide`/`resize`), which is the hook a _reusable_ component embedded inside a page uses to react to its host page's show/hide — not the mechanism for a component acting as the page itself. | Not stated on page for this specific interoperability detail                                                                                           | https://developers.weixin.qq.com/miniprogram/dev/reference/api/Page.html and .../api/Component.html (Component.html page body not retrievable beyond confirming Component() takes an Object; the `methods`-vs-`pageLifetimes` distinction is corroborated by community lifecycle write-ups) | The SDK wraps the `methods.on*` handlers the host defines; when one comes from a `behavior` instead, it hooks the merged `pageLifetimes.show/hide` / `lifetimes.detached` so the behavior's method is not shadowed |
